# Offline isolated rehearsal build

This tooling compiles public source for an explicitly supplied public Program ID.
It creates no identity, keypair, mint or on-chain account, has no wallet integration,
and never deploys, simulates or sends. A build is not authorization to execute it.
The test fixture is a fixed public byte value, not an approved deployment identity.

## Separate from historical tooling

`build:devnet` remains the historical-identity regression build. Do not retarget it,
Anchor.toml or the release `declare_id!` for a rehearsal. Root Anchor.toml still
contains historical/release identities and a default wallet path for legacy CLI
usage; do not use `anchor deploy` or `anchor keys sync`. The rehearsal workspace
contains no Anchor.toml, wallet setting, copied tests, or deployment key file.
Root Cargo.toml/lock and program source remain unchanged.

Agave 3.1.10's [build-sbf postprocessor](https://github.com/anza-xyz/agave/blob/v3.1.10/platform-tools-sdk/cargo-build-sbf/src/post_processing.rs)
automatically generates a program keypair if absent. Thus the new script does NOT
invoke `cargo build-sbf`, even with a separate output directory. It calls the
explicitly installed platform-tools Cargo/Rust compiler for `sbpf-solana-solana`
and `llvm-objcopy --strip-all` directly, offline and frozen. It neither installs
nor links toolchains. Use the reviewed platform-tools v1.52/Rust 1.89.0 installation.
This relies on trusted installed tools, dependency cache and local Cargo configuration;
it is not a hermetic compiler sandbox or an independent toolchain attestation.

## Public inputs and commands

An operator must approve/provide the public isolated ID separately. No ID defaults
from a wallet, environment, Anchor.toml, historical configuration or test fixture.
Missing, malformed, zero, release, historical-program and historical-mint IDs fail
before any workspace is created. The build does not accept a mint: the mint remains
a separate approved input to `prepare:rehearsal`, which forbids historical PAPA.

Preparation only (replace the descriptive placeholder with the approved public ID):

```sh
npm run build:rehearsal -- --program-id APPROVED_PUBLIC_PROGRAM_ID
```

Compile using the explicit directory of the existing reviewed platform tools:

```sh
npm run build:rehearsal -- --program-id APPROVED_PUBLIC_PROGRAM_ID --build --platform-tools /absolute/path/to/platform-tools
```

Each invocation creates a fresh directory under `target/rehearsal-builds/`; no
shared target cache or old rehearsal binary is reused. It copies only Rust source
and manifests/lock/toolchain files, rewrites exactly one release `declare_id!` in
the copy, and records original and prepared source hashes. No root file is edited.
The existing release build record must match the current Rust inputs and IDL hash.
The workspace's `idl.json` preserves that ABI and changes only the address; its
origin is explicitly recorded as adapted, not independently generated by Anchor.

Verify the resulting workspace against the same explicit public ID and current
source/IDL inputs:

```sh
npm run build:rehearsal -- --program-id APPROVED_PUBLIC_PROGRAM_ID --verify /absolute/path/to/rehearsal-workspace
```

`manifest.json` records source, prepared-file, compiler/tool, builder and binary
SHA-256 hashes, exact commands and status. Only `built-not-runtime-verified` passes
verification. `prepared-not-built`, `building` and `failed` do not. A killed build
may retain `building`; do not interpret the existence of program.so as success.
The verifier checks file bytes, program identity, ELF header and presence of the
public ID bytes. It rejects symlinks in public input paths and does not follow
manifest-supplied file paths. Preserve the public manifest and its SHA-256 outside
the workspace during review; a self-authored manifest is not an independent attestation.
An embedded-byte check alone does not prove executable behavior. Independent
rebuild, runtime verification and eventual deployed ProgramData comparison remain
necessary before treating this as a validated rehearsal candidate.

The script executes no Rust integration tests because they create ephemeral VM
signers. Current regression tests mock compiler execution; a separate local compiler
smoke check can use a fixed public fixture without creating its private identity.
No automatic deployment commands are emitted.

## Historical script protections

All seven signing devnet scripts retain their fixed historical program and mint.
Before loading any explicitly configured external signer they require
`PAPA_ALLOW_HISTORICAL_DEVNET` to equal the historical program's public ID. This is
an accidental-use interlock, not human signature authorization. There is no default
wallet fallback. Their main functions validate both IDs and the full Devnet genesis
hash before work or sending. The hash is the full [Solana genesis identifier](https://github.com/solana-labs/solana/blob/master/sdk/src/genesis_config.rs),
not the shortened CAIP-2 network ID. RPC failure also stops execution.

These legacy tools still read explicit JSON signers after opt-in and can send;
they remain outside the rehearsal route. Never enable them to bypass wallet-held
review. The readonly snapshot/program/test scripts keep their historical purpose;
none becomes a rehearsal client merely because a new binary exists. No public-ID
check proves private-key custody or that a proposed signer is exclusively Devnet.

## Evidence boundaries

interlocks. TESTED: see handoff for local regression and compiler smoke evidence.
EXTERNALLY VERIFIED: only the hosted workflow's actual commit and result.
PENDING: approved public rehearsal identities/mint, independently verified binary,
